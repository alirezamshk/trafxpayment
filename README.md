# TrafxPayment — درگاه پرداخت رمزارز چندپذیرنده‌ای

درگاه پرداخت خودمیزبان (self‑hosted) شبیه NOWPayments / Cryptomus:
پذیرندگان (مشتریان شما) با API یا پنل فاکتور می‌سازند، مشتریانشان پرداخت می‌کنند، واریز **به‌صورت خودکار روی بلاکچین تایید می‌شود**، کارمزد شما کسر می‌شود و مانده طبق زمان‌بندی (روزانه / هفتگی / دستی) به کیف پول پذیرنده تسویه می‌شود.

## امکانات

| بخش | توضیح |
|---|---|
| شبکه‌ها | TRON (TRX، USDT‑TRC20)، Ethereum (ETH، USDT‑ERC20)، BSC (BNB، USDT‑BEP20)، Polygon (POL، USDT)، TON (TON، USDT‑TON) |
| آدرس واریز | آدرس یکتای HD برای هر فاکتور (EVM/TRON)؛ برای TON آدرس خزانه + کامنت یکتا (Memo) |
| تایید خودکار | شمارش تاییدیه، کشف reorg و تراکنش ناموفق، رد USDT جعلی (فقط قرارداد رسمی)، پرداخت ناقص/اضافه/دیرهنگام |
| قیمت | فاکتور به USD (یا هر ارز فیات CoinGecko) یا مستقیم به رمزارز؛ نرخ هنگام صدور قفل می‌شود |
| چندپذیرنده | هر پذیرنده: پنل، چند کلید API، Webhook امضاشده، کارمزد اختصاصی، زمان‌بندی تسویه، آدرس تسویه برای هر ارز |
| حسابداری | دفتر کل (ledger) غیرقابل‌ویرایش: دریافت، کارمزد، تسویه، برگشت تسویه، اصلاحیه |
| تسویه | خودکار طبق زمان‌بندی + حداقل مبلغ، یا درخواستی؛ در صورت تمایل نیاز به تایید مدیر |
| Sweeper | انتقال خودکار وجوه از آدرس‌های فاکتور به کیف پول داغ (با شارژ خودکار گس/TRX) |
| پنل مدیر | درآمد کارمزد، بدهی به پذیرندگان، تایید/رد تسویه، اصلاحیه موجودی، واریزهای نامشخص، وبهوک‌های ناموفق |
| صفحه پرداخت | فارسی، موبایل‌فرندلی، QR، شمارش معکوس، انتخاب ارز توسط مشتری، به‌روزرسانی زنده |

## معماری و امنیت کلیدها

```
                  ┌──────────── PostgreSQL ────────────┐
                  │                                     │
   api  (xpub فقط)    worker  (xpub فقط)          signer  (mnemonic)
   - REST API         - watcher های بلاکچین         - sweep به کیف داغ
   - پنل‌ها           - تایید/انقضا                  - ارسال تسویه‌ها
   - صفحه پرداخت      - وبهوک، زمان‌بندی تسویه
```

- **API و worker هیچ کلید خصوصی ندارند**؛ فقط `xpub` برای ساخت آدرس. اگر سرور وب هک شود، وجهی قابل برداشت نیست.
- **signer** تنها پروسه‌ای است که `SIGNER_MNEMONIC` دارد. آن را روی سرور جدا، بدون پورت باز، اجرا کنید.
- مسیرها: آدرس فاکتورها `m/44'/60'/0'/0/i` و `m/44'/195'/0'/0/i`؛ کیف داغ `m/44'/{60,195}'/1'/0/0`؛ TON `m/44'/607'/0'` (SLIP‑10، wallet v4).
- هش تراکنش تسویه **قبل از ارسال** در دیتابیس ذخیره می‌شود تا پس از کرش، پرداخت دوباره انجام نشود.

## راه‌اندازی

```bash
npm install
npm run keys:generate        # mnemonic + xpub ها + آدرس کیف‌های داغ را چاپ می‌کند
cp .env.example .env         # EVM_XPUB, TRON_XPUB, TON_TREASURY_ADDRESS, RPC ها و API key ها
cp .env.signer.example .env.signer   # SIGNER_MNEMONIC (فقط سرور signer)
docker compose up -d --build
docker compose run --rm api node dist/bin/create-admin.js --email you@site.com --password '...'
```

سپس:
1. کیف‌های داغ را برای کارمزد شبکه شارژ کنید (ETH/BNB/POL، TRX، TON).
2. به `/admin` بروید، پذیرنده بسازید و کارمزدش را تعیین کنید (کلید API اولیه نمایش داده می‌شود).
3. پذیرنده در `/panel` آدرس تسویه هر ارز و زمان‌بندی را تنظیم می‌کند.

توسعه محلی: `npm run migrate`، `npm run dev:api`، `npm run dev:worker`، `npm run dev:signer`.

## API پذیرنده

احراز هویت: `Authorization: Bearer txp_...`

| متد | مسیر | توضیح |
|---|---|---|
| POST | `/v1/invoices` | ساخت فاکتور: `price_amount`, `price_currency`, `asset?`, `order_id?`, `description?`, `success_url?`, `cancel_url?`, `metadata?`, `expires_in_minutes?` |
| GET | `/v1/invoices/:id` | وضعیت + تراکنش‌ها |
| GET | `/v1/invoices?status=&limit=&before=` | فهرست |
| POST | `/v1/invoices/:id/cancel` | لغو (فقط بدون پرداخت) |
| GET | `/v1/balances` | موجودی قابل تسویه |
| GET/POST | `/v1/payouts` | تاریخچه / درخواست تسویه `{asset}` |
| GET | `/v1/assets` | ارزهای فعال (عمومی) |

وضعیت فاکتور: `pending` → `confirming` → `paid`؛ همچنین `partially_paid`، `expired`، `cancelled`.
پاسخ شامل `payment_url` است؛ مشتری را به آن هدایت کنید.

### Webhook

هدرها: `x-webhook-id`، `x-webhook-timestamp`، `x-webhook-signature` = `HMAC_SHA256(secret, timestamp + "." + body)`.
رویدادها: `invoice.confirming|paid|partially_paid|expired|cancelled`، `payout.created|completed|failed|rejected`.
پاسخ غیر 2xx تا `WEBHOOK_MAX_ATTEMPTS` بار با تاخیر افزایشی تکرار می‌شود. نمونه کد Node و PHP در تب «راهنمای اتصال» پنل هست.

## جریان پول

1. فاکتور `paid` می‌شود ← در ledger: `+payment` و `-fee` (درصد کارمزد پذیرنده در لحظه ثبت).
2. پرداخت اضافه یا دیرهنگام بعد از `paid` هم (منهای کارمزد) اعتبار می‌گیرد.
3. در ساعت `SETTLEMENT_HOUR_UTC` برای پذیرندگان سررسیده، کل موجودی هر ارز (اگر ≥ حداقل) به یک payout تبدیل و از موجودی کسر (رزرو) می‌شود.
4. با `PAYOUT_REQUIRE_APPROVAL=true` مدیر تایید می‌کند؛ signer از کیف داغ ارسال و تا تایید روی شبکه پیگیری می‌کند.
5. رد یا شکست تسویه ← `payout_reversal` و برگشت مبلغ به موجودی.

داشبورد مدیر «بدهی به پذیرندگان» را نشان می‌دهد: حداقل مبلغی که باید در کیف داغ باشد.

## پیش از راه‌اندازی واقعی (مهم)

- **ابتدا روی تست‌نت یا با مبالغ بسیار کم** کل چرخه (واریز ← تایید ← sweep ← تسویه) را روی هر شبکه امتحان کنید. پارسرهای TronGrid و toncenter بر اساس مستندات نوشته و با داده نمونه تست شده‌اند، نه با API زنده.
- برای حجم بالا از RPC/API پولی (TronGrid key، toncenter key، Alchemy/QuickNode) استفاده کنید؛ watcher ترون برای هر فاکتور فعال جدا poll می‌کند.
- واریز ETH/BNB از طریق قرارداد هوشمند (internal transaction) توسط اسکن بلاک دیده نمی‌شود؛ در «واریزهای نامشخص» یا با sweep بعدی مشخص می‌شود.
- در TRON بدون انرژی، هر انتقال USDT حدود ۱۵ تا ۳۰ TRX می‌سوزاند؛ برای کاهش هزینه، TRX را در کیف داغ stake کنید و انرژی delegate کنید.
- فقط موجودی لازم برای تسویه را در کیف داغ نگه دارید و مازاد را دستی به کیف سرد منتقل کنید.
- اجرای سرویس پرداخت امانی (custodial) برای اشخاص ثالث ممکن است مشمول قوانین و مجوزهای حوزه قضایی شما باشد.
